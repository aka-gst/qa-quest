# QA Quest

Интерактивный курс из трёх ступеней: питон с нуля, тестирование, работа и тесты
с LLM. Python выполняется прямо в браузере — устанавливать не нужно ничего.
Это принципиальный выбор: установка питона на телефоне — то место, где
отваливается большинство новичков.

## Что уже работает

- **Настоящий Python в браузере.** Pyodide (CPython 3.14) в web worker'е.
  Код ученика выполняется по-настоящему, проверки читают его переменные,
  вызывают его функции и сравнивают вывод терминала.
- **Два режима на одном материале.** «Пробежать» — суть и одна задача;
  «разобрать» — объяснение, где применяется, типичная ошибка, примеры и три
  задачи. Переключается в любой момент, прогресс общий.
- **Два слоя на ступенях 2 и 3.** Сначала тренажёр в браузере — уроки, которые
  пишутся здесь и проверяются автоматически. Потом практикум на своей машине —
  готовые эксперименты, которые подтягиваются из `course.json` и проверяются
  чек-листом. Всего 61 урок: 35 тренажёра (103 задачи с автопроверкой) и
  26 экспериментов практикума.
- **Геймификация.** Карта уроков, XP и уровни, серии дней, последовательная
  разблокировка уроков и ступеней.
- **Человеческие ошибки.** Трассировка обрезается до файла ученика, к каждому
  типу ошибки добавлено объяснение на русском. Бесконечный цикл останавливается
  сам через восемь секунд и объясняет, что произошло.
- **Прогресс и вход.** Локально — всегда, а при доступном общем сервисе
  аккаунтов aka-gst прогресс синхронизируется между устройствами. Вход у сайта
  один и живёт на уровне сайта, см. [docs/shared-account.md](docs/shared-account.md).

## Запуск

Нужен любой статический сервер: страница использует ES-модули и web worker.

```bash
python3 -m http.server 4173
```

Открыть <http://127.0.0.1:4173>.

Первый запуск кода скачивает Pyodide (около 13 МБ), дальше он берётся из кэша
браузера. Требуется браузер с module worker'ами: Chrome 80+, Safari 15+,
Firefox 114+.

Чтобы не зависеть от чужого CDN, копию Pyodide можно положить рядом:

```bash
sh tools/fetch-pyodide.sh
```

Страница сама находит `vendor/pyodide/` и грузит Python оттуда; если копии нет,
идёт на jsDelivr и пишет об этом предупреждение в консоль — на домене такое
означает неполную выкладку. Каталог не версионируется.

Скрипт пиньит и версию, и контрольные суммы всех пяти файлов и сверяет их после
скачивания: 9,5 МБ wasm исполняются в браузере каждого посетителя, и подмена на
стороне CDN не должна проходить молча. Рядом кладётся лицензия Pyodide
(MPL-2.0) и `NOTICE.md` с происхождением — файлы раздаются с нашего домена,
значит и лицензия должна лежать там же.

### Как устроена проверка задачи

Задача описывает проверки декларативно, а исполняет их Python внутри воркера:

```js
checks: [
  { label: 'is_success(201) возвращает True', kind: 'call', fn: 'is_success', args: [201], equals: true },
  { label: 'В терминале появилось «Q-Bot online»', kind: 'stdout', mode: 'equals', value: 'Q-Bot online' },
  { label: 'critical равен [4, 5, 3]', kind: 'var', name: 'critical', equals: [4, 5, 3] },
  { label: 'Использован цикл for', kind: 'source', pattern: '^\\s*for\\s+' },
  { label: 'В хранилище две записи', kind: 'py', expr: 'len(storage) == 2' },
]
```

Доступные виды: `stdout` (`equals`, `contains`, `absent`, `regex`, `lines`),
`var`, `call` (`equals`, `raises`, `prints`), `source` (в том числе `absent`)
и `py` — произвольное выражение над пространством имён решения.

### Практикум: почему тексты не пишутся здесь

Ступени 2 и 3 существуют как практикумы в отдельных репозиториях: DOCX в
`agent-lab` и Markdown в `ai-agent-service-lab`. Сборка кладёт рядом с
опубликованными страницами `course.json` по схеме `aka-gst.course/1`, и
QA Quest читает его напрямую — 16 экспериментов на второй ступени и 10 на
третьей. Правка текста здесь исчезла бы при следующей пересборке, поэтому её
здесь нет: [src/content/practicum.js](src/content/practicum.js) только
проецирует готовые поля на урок.

Эти ступени нельзя проверить автоматически: там ставят Ollama, поднимают шлюз и
гоняют pytest на своей машине. Поэтому критерий завершения — чек-лист
`done_when` из практикума, который участник отмечает сам.

Для разработки нужны локальные копии:

```bash
sh tools/fetch-practicum.sh
```

На домене они не нужны: практикумы лежат соседней папкой `/praktikum/`, и
приложение находит их само. Если `course.json` недоступен, ступени остаются с
одним тренажёром и ничего не ломается.

### Стенды

Урок может объявить `preamble` — код, который выполняется до решения в том же
пространстве имён. Так ученик получает объект для тестирования: мини-раннер
`run_tests()` вместо pytest, смоделированный шлюз `gateway_request()` с теми же
правилами, что у настоящего local-agent-gateway, и смоделированная модель
`ask_model()` с детерминированными ответами и канарейкой в системном промпте.

Модель и шлюз смоделированы сознательно и это сказано ученику прямо: без ключей,
без сети и с одинаковым поведением у всех. Навык, которому учит третья ступень, —
не «поболтать с моделью», а построить вокруг неё проверяемый контур.

## Проверка проверок

```bash
sh tools/selftest.sh
```

Отдельный скрипт, который ставит каждую проверку в условия, где она обязана
упасть: подменённая контрольная сумма Pyodide, разошедшиеся версии, неверное
решение задачи, посторонний файл в выкладке. Зелёная проверка ничего не
доказывает, пока не видел её красной — за один день так «прошли» тест подмены
суммы, бивший мимо строки, и проверка выкладки, смотревшая на 18 КБ из 13 МБ.

По той же причине выкладка перечисляет разрешённое, а не запрещённое. Список
исключений дорос до девяти пунктов, и `.githooks` всё равно проскочил бы на
публичный сервер: перечислить всё лишнее нельзя. Список разрешённого ошибается
в безопасную сторону — забытое не публикуется.

## Проверка содержания

Каждое эталонное решение прогоняется тем же движком, что и в браузере, но в
обычном CPython. Проверяется, что решение проходит все проверки задачи и что
заготовка их не проходит:

```bash
python3 tools/verify_content.py
```

## Источники материала

- Ступень 2 опирается на практикум по проверке шлюза (`agent-lab`) и набор из
  50 автотестов `local-agent-gateway`: контракт, границы, негативные сценарии,
  дисциплина PASS / FAIL / NOT PROVEN.
- Ступень 3 — на лаборатории `ai-agent-service-lab` (модель как API,
  структурированный вывод, агент с инструментами, evaluation) и на слой оценок
  `local-agent-gateway`: обязательные термины, пороги, метрики, prompt-injection canary.

## Выкладка

```bash
sh tools/deploy.sh            # обновить локальное дерево сайта
sh tools/deploy.sh --deploy   # и выложить на aka-gst.ru/qa-quest/
```

Перед копированием скрипт прогоняет `verify_content.py` и отказывается
выкладывать курс, в котором эталонные решения не проходят свои проверки.
