# QueQuest 4.0 — First-hour engagement design

## Цель

Игрок без опыта программирования должен начать с понятного физического действия, получить
заметный payoff от автоматизации и только потом увидеть минимальную форму Python. Игрок с
опытом проходит те же события быстрее: отдельной «упрощённой кампании» нет.

## Ранний interest beat

1. **ACTION** — взять и донести первый оплачиваемый ящик.
2. **PATTERN** — три ручных маршрута загораются в `LEARNING PATH`.
3. **DISCOVERY** — найден Python-чип, но синтаксис ещё не спрашивается.
4. **PAYOFF** — машина повторяет уже понятную работу и зарабатывает без рук игрока.
5. **SURPRISE** — физическая кнопка исчезает; старый способ больше не работает.
6. **CHOICE** — красный груз ломает слепую автоматизацию и рождает условие.
7. **REMIX** — необязательный Sorter Bay позволяет играть с тем же условием на новых наборах.
8. **SYSTEM** — неизвестная длина очереди рождает `while/list`.
9. **MASTERY** — две линии рождают `def`, потому что копировать поведение неудобно.

Эта последовательность специально чередует действие, открытие, payoff, неожиданность и
выбор. Она не должна превращаться в линейный рост количества текста.

## Правила объяснения

- **Action before term.** Термин не появляется до того, как игрок столкнулся с его физической причиной.
- **Proof in the world.** Правильность видна по движению ящиков/очереди/машины, а не только по надписи PASS.
- **Counterexample instead of punishment.** Ошибка показывает объект, который повёл себя не так; прогресс не отнимается.
- **Same game, different help density.** `A+ / A−` не меняет правила мира и не создаёт отдельную траекторию.
- **Real errors stay real.** SyntaxError/NameError/IndentationError приходят из CPython; guided mode лишь добавляет понятный hint.
- **Optional mastery toys.** Повторное применение навыка живёт в небольших системных игрушках, а не в обязательных десяти одинаковых вопросах.

## SORTER BAY

Физическая модель: `SOURCE → PASS / HOLD`. Каждый ящик имеет несколько наблюдаемых
признаков. Заказ формулируется человеческим языком. Игрок выбирает правило и сразу видит
полную маршрутизацию восьми объектов. Python скрыт до первого работающего решения.

Уровни ремикса:

- 1: один признак / простое сравнение;
- 2: два признака и `and`;
- 3: `and / or / not`, но всё ещё на видимых объектах, а не абстрактных truth-table.

## Что измерять в человеческом playtest

Не считать заранее заявленные «20 часов» доказанными. Для первого часа фиксировать:

- время до первого осмысленного действия;
- время до первого ощущения «машина делает это за меня»;
- места с >10–15 сек без нового действия;
- сколько раз подсказка A+ реально помогла продолжить;
- пробует ли игрок другую сортировочную схему добровольно после первого успеха;
- может ли объяснить результат через поведение объекта, не используя термин Python;
- где опытный игрок хочет убрать объяснение и где новичок просит ещё один пример.

## Источники дизайна

Использованы как принципы, без копирования текста/ассетов:

- Jesse Schell, *The Art of Game Design*: кривая интереса и осмысленный выбор;
- Scott Rogers, *Level Up!*: вся игра может постоянно обучать новым действиям, а не отделять обучение в один tutorial-level;
- присланные практикумы по агентам: наблюдаемое доказательство важнее заявления системы; это же правило применяется к раннему Python — мир должен показать результат.
