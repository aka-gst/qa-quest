# QueQuest 11.0 — RELEASE WEEK

## Фантазия игрока

До этого момента QueQuest последовательно даёт власть:

1. сделать руками;
2. понять причинность;
3. выразить её кодом;
4. сохранить как blueprint;
5. дать автомату жить без себя.

11.0 добавляет следующий естественный вопрос: **что происходит с кодом завтра?**

Игрок больше не учится на одноразовой задаче. Он обслуживает уже знакомый цифровой
город, который зависит от его прошлых решений. Новое удовольствие — не «я нашёл
правильную кнопку», а «я меняю живую систему и сохраняю контроль над последствиями».

## Новичковый принцип

Термины не являются входом. В A+ игрок сначала видит:

- «партнёр прислал новую форму заказа, старые ещё существуют»;
- «на фестивале очередь растёт быстрее линии»;
- «Q-Bot отвечает быстро, но старой инструкцией»;
- «появилась новая опасная кнопка»;
- «один общий patch трогает сразу много мест».

Только потом эти явления получают имена: compatibility adapter, bounded scale,
freshness/provenance, allowlist, release train.

## Основная петля

`PATCH → TEST → CANARY → OBSERVE → DEPLOY / ROLLBACK`

Важно: это не линейный tutorial, где нужно обязательно нажать пять кнопок.

- безопасный low-risk patch после зелёного стенда может выйти сразу;
- заметный риск требует маленького живого canary;
- canary без наблюдения не является доказательством;
- regression на тесте — хороший исход: город не пострадал;
- regression на canary ограничивает blast radius;
- rollback — сохранение управляемости, а не поражение;
- плохой direct deploy может реально ухудшить состояние смены, но не уничтожает
  долгосрочный профиль.

## Q-Bot

Q-Bot впервые становится не только обучаемым компаньоном, но и автором patch proposal.
Это намеренно двусмысленная роль: он может сгенерировать полезную идею или слишком
смелое обобщение (`global rename`, `unbounded scale`, `cache TTL ↑`, wildcard authority,
big-bang deploy).

Игровой урок формулируется без морализаторства: **уверенность автора patch-а не
является evidence его безопасности**.

## Пять authored-дней

1. **Новая форма** — compatibility / migration.
2. **Город ускорился** — bounded capacity вместо бесконечного scale.
3. **Умный, но старый** — freshness + provenance.
4. **Новая кнопка** — capability отдельно от authority.
5. **Ночь релиза** — несколько границ и минимальный blast radius.

## Mastery

После 5/5 открывается бесконечный deterministic `RELEASE RUN #seed`.
После понимания цикла игрок может формализовать его в настоящем Python:

```python
def decide_release(patch, evidence):
    if evidence["tests"] is False:
        return "reject"
    if evidence["canary"] is False:
        return "rollback"
    if patch["risk"] >= 3 and evidence["canary"] is None:
        return "canary"
    return "deploy"
```

Скрытые проверки смотрят на поведение, а не на конкретный текст решения.

Auth/model secrets по-прежнему не относятся к игровому профилю.

## Что unit-тесты не доказывают

- что игрок эмоционально начинает защищать уже знакомые сервисы;
- что canary интуитивно понятен до появления термина;
- что плохой Q-Bot patch воспринимается как осмысленный риск, а не ловушка;
- что несколько дней подряд создают чувство истории, а не повторение UI.

Эти четыре пункта — обязательная human-playtest boundary.
