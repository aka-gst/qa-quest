# QueQuest · game-first design 0.2

Этот файл специально разделяет **сохранённые решения автора** и **новые
предложения реализации**. Новые предложения не объявляются старым каноном.

## 1. Сохранённый канон

Первый эпизод не менять: три ящика руками → начальник → дверь → падение чипа →
видимый разъём → вставка → рука начинает делать ту же работу сама. До чипа рука
не работает. После чипа Python от игрока не требуется.

Следующая учебная логика уже зафиксирована в проектных документах: готовая
кнопка исчезает и создаёт необходимость в `print`; красный ящик ломает слепое
правило и создаёт необходимость в `if`. Команды появляются из проблемы, а не из
списка уроков. Первый бот должен появиться рано, когда игрок уже понял действие,
повторение и условие.

Вика — более поздняя ступень. Сохранённые признаки: синее парящее
получеловеческое/женское компьютерное лицо без тела; реплика «А вот и ты»
принадлежит Вике. Вирус — поздний сюжетный beat. Friends-defense должен быть
про разных друзей, разные атаки/защиты и обучение после победы, а не про
безличное PvP.

Прогресс game-first версии local-first. Shared account/backend нельзя считать
готовым без отдельной проверки.

## 2. Уже реализовано в 0.2

### Глава 1 · выгода до синтаксиса

- три ручные оплачиваемые доставки;
- начальник появляется только после третьей;
- хлопок двери предшествует падению чипа;
- установка чипа запускает шесть автодоставок без редактора кода;
- игрок видит ту же физическую работу и тот же денежный сигнал.

### Глава 2 · язык появляется из поломки

**Beat A — кнопки нет.** На самой машине отсутствует физическая кнопка. В
терминале `print("wake")` объясняется как способ снова послать сигнал.

**Beat B — автоматизация слепа.** Шесть белых грузов проходят, затем красный
ящик физически останавливает руку.

**Beat C — повторение + условие.** Новая мини-смена содержит несколько белых и
красных ящиков. Игрок собирает:

```python
for box in boxes:
    if box.kind != "red":
        arm.move(box, pallet)
```

Каждая строка переводится на язык мира прямо в терминале:

- `for` = «сделай этот блок для каждого ящика»;
- `if` = «выполни вложенное только если проверка истинна»;
- `arm.move` = одно разрешённое событие → одно движение реальной руки.

Награда: `PRINT`, `FOR`, `IF`, ранний `Q-Bot 0.1`.

## 3. Новая предлагаемая лестница кампании

Ниже — **новый design proposal**, а не восстановленный старый текст.

### Глава 3 · очередь растёт без тебя

**Игровая проблема:** одна партия ящиков заканчивается, игрок уходит, приходит
следующая. Одиночный запуск больше не достаточен.

**Навык:** состояние + цикл (`while` только когда он становится нужен).

**Игра:** игрок не пишет бесконечный цикл абстрактно. Он ставит сенсор очереди,
видит `queue_has_boxes()`, а затем учит Q‑Bot: пока очередь не пуста — обработай
следующий груз. Ошибка должна быть смешной и физической: бот продолжает ждать,
если условие выхода написано неверно; игра безопасно останавливает процесс и
объясняет, почему.

### Глава 4 · повторяемая процедура

**Проблема:** одинаковая логика нужна в двух разных местах склада.

**Навык:** функция + параметры.

Игрок сначала вручную копирует один и тот же набор блоков и замечает, насколько
это неудобно. Затем сворачивает его в `def route(box, target): ...` и подключает
две линии. Функция визуально становится «картриджем поведения», который можно
вставить в разные машины.

### Глава 5 · друзья / защита

Не делать generic PvP. До утверждения характеров не придумывать канонические
имена и биографии.

Предлагаемая механическая рамка: три **явно временные** роли друзей, каждая
обладает устойчивым приёмом — например наблюдение, фильтрация, восстановление.
Игрок защищает тренировочный сервер вместе с ними, а после победы один друг
разбирает конкретный приём, который только что спас команду. Код изучается после
игрового применения.

Темы, которые сюда естественно ложатся: переменные/адреса, списки событий,
функции, простая обработка входных данных, понятие доверенной/недоверенной
информации. Настоящие чаты, чужие аккаунты и реальные атаки не нужны.

### Глава 6 · Вика

Использовать только сохранённую визуальную границу и реплику «А вот и ты»;
новые детали характера до отдельного авторского решения считать системным
черновиком.

Механическая функция Вики: показать, что программа может иметь **состояние и
память**. Игрок уже умеет писать действия; теперь одно и то же сообщение должно
получать разную реакцию в зависимости от сохранённого состояния. Здесь удобно
учить словари/объекты и функции, не читая лекцию про структуры данных.

Текущая `art/future-vika.jpg` не соответствует точной сохранённой границе
«парящее лицо без тела», поэтому считать её только концепт-артом, а не финальным
каноническим изображением.

### Глава 7 · вирус / финал первой игры

Финальный противник должен ломать **предположения игрока**, а не иметь много HP:
неожиданный тип данных, пропущенное значение, таймаут, неверный порядок событий.

Здесь естественно появляются:

- `try/except` как защита от понятной поломки;
- тест как способ заранее воспроизвести поломку;
- лог как способ понять, что произошло ночью.

Это создаёт красивый мост к следующему продукту.

## 4. Мост в Pythonio

QueQuest заканчивается мыслью: «я могу заставить код управлять понятным мне
миром». Pythonio начинается с: «теперь сделай то же самое с реальной рутиной».

Не надо заново преподавать `print/for/if` лекциями. Pythonio может импортировать
флаг завершения QueQuest и дать короткое диагностическое вступление:

- файл/фото/текст = новый тип игрового груза;
- машина = функция/шаг pipeline;
- развилка = `if`;
- повтор = `for`;
- API = внешний механизм, которому мы посылаем команду;
- retry/idempotency/logging = уже production-надежность.

## 5. Старый QA Quest не выбрасывать

Старый курс с настоящим Pyodide, тестированием и LLM полезен как поздний
«лабораторный режим». Он не должен заменить game-first кампанию.

Ступени тестирования и LLM уже имеют отдельные source-of-truth и `course.json`.
Их тексты не копировать вручную в игру. После сюжетной кампании QueQuest можно
показать дверь «ЛАБОРАТОРИЯ»: она открывает импортированную практику, если она
доступна, либо остаётся необязательной.

## 6. Definition of Done первой полноценной версии

1. Новый человек без объяснений автора проходит главу 1 и может сказать: «раньше
   я таскал, теперь машина делает то же самое».
2. Во второй смене он понимает причину появления `print`, а не воспринимает его
   как пароль.
3. После красного груза своими словами объясняет `for` и `if` через ящики.
4. На телефоне 390×844 ни чип, ни терминал, ни красный ящик не требуют точного
   пиксельного попадания.
5. Сохранение восстанавливает начало каждой смены/задачи без двойной награды.
6. Friends/Vika/virus не изображают настоящую сеть или готовый backend.
7. Pythonio подключается как следующая игра/глава, а не как новая первая лекция.
