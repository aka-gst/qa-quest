# QueQuest 7.0 — OPS DESK

## Зачем эта ветка

OPS DESK добавляет новый тип удовольствия: не «собери правильный pipeline», а
**разберись, что произошло**. Игрок получает историю через рабочий стол и должен
свести несколько наблюдений в одну причинную цепочку.

Это заимствует сильный игровой язык desktop-hacker simulators: окна, сообщения,
терминал, карта связей, заметки и ощущение самостоятельного расследования. Но QueQuest
не симулирует реальные атаки. Все цели — синтетические внутренние системы фабрики,
API/LLM wrappers, очереди, сервисы и agent workflows.

## Что взяли из HackHub как референса

- рабочий стол как часть мира, а не меню;
- история, приходящая через сообщения/звонки/файлы;
- параллельное использование нескольких инструментов;
- визуальная карта связей;
- терминал как способ чувствовать контроль;
- расследование через улики вместо катсцены.

## Что сознательно НЕ переносим

- необходимость знать настоящие offensive security tools;
- строгий порядок параметров ради «реализма»;
- исчезающие подсказки после начала ввода;
- отдельный ручной turn-in после уже доказанного результата;
- линейность, где найденная вне скрипта информация не имеет смысла;
- currency/награды без игрового применения;
- handbook как единственное спасение, когда интерфейс не объяснил задачу.

## Базовый цикл CASE

1. `DISPATCH` даёт человеческий симптом.
2. Игрок сам выбирает, куда смотреть: сообщение, logs, trace map или runbook.
3. Найденное автоматически попадает в `NOTES`.
4. Минимум три независимых evidence нужны до закрытия кейса.
5. Игрок выбирает причинный диагноз.
6. Игрок выбирает действие, которое лечит именно эту причину.
7. Если гипотеза объясняет всю цепочку, CASE закрывается автоматически.
8. После пяти authored cases открываются бесконечные `DESK SHIFT #seed`.

## SAFE TERMINAL

Терминал — альтернативный интерфейс, не экзамен на память.

Доступные команды:

- `inbox`
- `logs`
- `trace`
- `files`
- `notes`
- `help`

Есть алиасы (`mail`, `log`, `map`, `docs`) и tab-completion уникального префикса.
Любое действие терминала можно выполнить мышкой/тапом. Реальные команды атак и
сканирования намеренно отсутствуют.

## Authored cases

### 01 · Призрачная квитанция

Timeout случился после записи, а retry создал повтор. Игрок приходит к
`unknown result after effect → idempotency`.

### 02 · Старая память

Q-Bot уверенно использует архивный chunk. Игрок видит, что высокая similarity не
доказывает актуальность: нужны provenance и eval.

### 03 · Зелёный, но не готов

`/health` зелёный, dependency сломана, `/ready` красный. Игрок физически разделяет
liveness и readiness.

### 04 · Молчащий поток

Provider и gateway отдают chunks, клиент буферизует до конца. Streaming становится
сквозным контрактом, а не «галочкой модели».

### 05 · «Тесты прошли»

Агент сообщает PASS, но command history пуст. Игрок учится отличать claim от evidence:
command + exit code + output.

## Доступность для новичка

A+ показывает короткую гипотезу Q-Bot человеческим языком. Она не является ответом и
не закрывает кейс. A− скрывает этот блок и оставляет только инструменты/evidence.

Игрок никогда не обязан печатать команду. Терминал существует для ощущения контроля
и плавного перехода к настоящему Python/CLI мышлению.

## Profile v6

Сохраняются:

- completed authored cases;
- solved infinite desk seeds;
- best case/incident score;
- XP ledger по уникальному case/seed.

Merge двух устройств объединяет прогресс монотонно. Старые profile v1–v5 мигрируют в
v6. Cloud-sync envelope принимает v2–v5 во время rollout.

## Что требует human playtest

Автотест не может доказать:

- хочется ли добровольно открыть четвёртый источник evidence;
- чувствуется ли CASE как расследование, а не форма с вариантами ответа;
- не слишком ли много текста в Dispatch на телефоне;
- хочется ли сыграть ещё один DESK SHIFT после authored-пятёрки;
- насколько terminal добавляет атмосферу, а не лишний интерфейс.
