# Первая мысль после WAKE — дизайн пилота

**Статус:** утверждено Сергеем 4 сентября 2026 словами «делай, мозг свободен».

## Цель

Сделать первый маленький, но настоящий мост от изучения Python к рождению собственного иного разума. Игрок не получает медаль за правильный ответ: выполненный Python меняет мир, будит механическую руку и одновременно впервые оживляет существо-помощника.

Пилот должен доказать одну цепочку:

`print("WAKE")` → `capability.unlocked` → безопасный Tulpa-adapter → локальный fake Gateway → `sleeping → waking → awake`.

## Игровое ощущение

До команды рядом с рукой спит бесформенное тёмное «семя». После настоящего выполнения Python оно не просто зажигает лампу:

1. сжимается и выпускает два расходящихся кольца;
2. собирает видимый зрачок и начинает следить за рукой;
3. произносит первую короткую мысль: «Я слышу машину. Теперь научи меня понимать её.»

Переход длится 1–2 секунды. Игрок видит причинность: его строка кода стала новым существом и новой способностью. При `prefers-reduced-motion` кольца не пульсируют, но три состояния различаются формой, контрастом и текстом.

## Границы ответственности

- QueQuest владеет миссией, выполнением Python, событием способности, состоянием существа, визуальным переходом и счётчиками локальной приёмки.
- Tulpa в этом пилоте представлена узким адаптером: он превращает только разрешённое синтетическое событие в фиксированный запрос. Репозиторий `/Users/gst/dev/tulpa` не меняется.
- Local Agent Gateway представлен детерминированной in-process фикстурой с тем же смыслом границы: один очищенный запрос — один поток ответа. Репозиторий `/Users/gst/dev/local-agent-gateway` не меняется.
- Реальная модель, сеть, ключи, инструменты компьютера, файлы пользователя, голос, Telegram, облако и выкладка не входят в пилот.

## Контракт события

Единственный разрешённый объект:

```js
{
  version: 1,
  type: 'capability.unlocked',
  capability: 'machine-listening',
  mission: 'warehouse-arm',
}
```

Принимаются ровно эти четыре поля и ровно эти значения. Лишнее поле, неизвестная способность, другая версия или не-объект отклоняются до вызова адаптера и Gateway.

Исходный Python, stdout, имя игрока, история, путь к файлу, токен, `privateWorkNotes` и произвольный текст не входят в событие и не могут попасть в запрос.

## Запрос адаптера

После валидации адаптер создаёт фиксированный запрос:

```js
{
  model: 'local-fake-other-mind',
  stream: true,
  messages: [
    {
      role: 'system',
      content: 'Ты — только что проснувшееся семя иного разума. Ответь одной короткой фразой без команд, файлов и личных данных.',
    },
    {
      role: 'user',
      content: 'Открыта способность machine-listening в миссии warehouse-arm.',
    },
  ],
}
```

Фикстура Gateway принимает только этот allowlisted payload и отдаёт фразу небольшими частями, чтобы ответ был видим как живой процесс. Она хранит для отладки только число вызовов и последний очищенный запрос, но не журнал произвольных body.

## Идемпотентность и отказ

- Событие создаётся только после успешного `runWake()` с точным stdout `WAKE`.
- Одна способность открывается один раз за сессию. Повторный `WAKE` не создаёт второе событие, награду, запрос или переход.
- `WAKЕ` с кириллической `Е`, `SLEEP` и любой другой stdout не создают событие.
- Сначала состояние меняется на `waking`; на `awake` оно переходит только после полного ответа Gateway.
- При отказе Gateway существо не изображает пробуждение: после попытки связи оно переходит в отдельное состояние `silent`; игра и сохранение продолжают работать, а игрок видит: «Разум сейчас молчит. Рука всё равно тебя услышала.»
- Ошибка не показывает request body, stack, URL, токен или внутренние детали.

## Наблюдаемая приёмка

Локальный debug snapshot показывает только безопасные числа и состояния:

- `events` — число принятых `capability.unlocked`;
- `gatewayCalls` — число вызовов fake Gateway;
- `transitions` — последовательность `sleeping`, `waking`, `awake` или `sleeping`, `waking`, `silent`;
- `phase` и готовую публичную реплику.

Положительный прогон обязан дать `1 / 1 / sleeping→waking→awake`. Отрицательные прогоны обязаны дать `0 / 0` и не менять визуальное состояние. Отдельно сохраняется прежний сценарий `arm.move`.

## Не входит

Нет реального LLM, кросс-origin API, долговременной памяти, прокачки существа, автобоя, валюты, сетевых друзей, реальных инструментов, публикации и переноса в Unity/Unreal. Пилот проверяет только киллер-момент: «я написал одну строку — и в мире родился тот, кого я буду растить».
