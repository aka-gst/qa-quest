# Общий аккаунт aka-gst

QA Quest не заводит собственный вход. Он обращается к тому же сервису аккаунтов,
который уже написан в Лиле (`leela-mvp/backend/server.py`): таблицы `accounts`,
`email_verifications`, `auth_sessions` и кука `leela_auth` с `Path=/`.

Условие работы одно: и Лила, и QA Quest должны отдаваться с одного origin
(`aka-gst.ru`), а `/api/auth/*` — проксироваться на сервис аккаунтов. Тогда
одна кука обслуживает оба проекта, и третьего логина на сайте не появляется.

## Что клиент уже умеет

`src/auth.js` реализует ровно существующий протокол Лилы:

| Метод и путь | Тело запроса | Ответ |
|---|---|---|
| `GET /api/auth/me` | — | `{"authenticated": false}` или `{"authenticated": true, "email": "...", "email_verified": true}` |
| `POST /api/auth/register` | `{"email", "password"}` (пароль от 12 символов) | `201 {"created": true, "verification_required": true}`, `409 email_unavailable` |
| `POST /api/auth/verify` | `{"token"}` | `{"verified": true}` и установленная сессия |
| `POST /api/auth/login` | `{"email", "password"}` | `{"authenticated": true, "email"}`, `401 invalid_credentials`, `403 email_not_verified` |
| `POST /api/auth/logout` | — | `{"authenticated": false}` |

Если `GET /api/auth/me` не отвечает или отдаёт не-JSON, клиент переходит в
состояние `offline`: кнопка входа объясняет, что сервис недоступен, а прогресс
продолжает жить в `localStorage`. Ни один урок при этом не ломается.

## Чего в сервисе ещё нет

Для синхронизации прогресса нужны два эндпоинта. Они не привязаны к QA Quest:
`scope` в пути позволяет тем же способом хранить состояние Лилы и лидерборда игр.

```
GET  /api/progress/{scope}    ->  200 {"state": {...}, "updatedAt": 1756400000000}
                                  200 {"state": null} — у аккаунта ещё нет записи
PUT  /api/progress/{scope}    <-  {"state": {...}, "updatedAt": 1756400000000}
                              ->  200 {"saved": true}
```

Требования:

- оба метода работают только для аутентифицированного аккаунта, иначе `401`;
- `scope` ограничен коротким списком (`qa-quest`, `leela`, `games`) — не свободная строка из запроса;
- `state` хранится как непрозрачный JSON, сервер его не интерпретирует;
- разумный предел размера тела (например, 256 КБ) и `413` при превышении;
- таблица: `progress(account_id, scope, state TEXT, updated_at INTEGER, PRIMARY KEY(account_id, scope))`.

## Как объединяется прогресс

Слияние делает клиент (`mergeState` в `src/store.js`), а не сервер:

- решённые задачи объединяются по принципу «решено хотя бы где-то»;
- у общей задачи сохраняется более раннее время решения;
- открытые ступени объединяются по «открыто хотя бы где-то»;
- рекорд серии берётся максимальный, текущая серия — из более свежего дня;
- сохранённый код берётся из более свежего состояния.

Такой порядок означает, что потерять решённую задачу при переключении устройств
нельзя. Серверу для этого ничего знать про формат не нужно.

## Порядок внедрения

1. Поднять сервис аккаунтов на `aka-gst.ru` (сейчас код живёт в Лиле).
2. Добавить `GET`/`PUT /api/progress/{scope}` по описанию выше.
3. В QA Quest ничего не менять: клиент найдёт эндпоинты сам. Если сервис
   стоит на другом хосте, путь задаётся через `window.QA_QUEST_API` до загрузки
   `src/main.js`, и на сервисе нужно разрешить CORS с credentials.
