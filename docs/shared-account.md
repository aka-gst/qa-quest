# Общий аккаунт aka-gst

QA Quest не заводит собственный вход. Он обращается к общему сервису аккаунтов
сайта — тому же, которым пользуются Лила и лидерборд игр.

Сервис живёт на уровне сайта: `Zakriva/ops/accounts`, рядом с `ops/leaderboard`.
Учётная запись принадлежит человеку и сайту, а не отдельному проекту. Раньше код
аутентификации лежал внутри `leela-mvp/backend/server.py` — вход впервые
понадобился там, и код написали на месте. Это была случайность, а не решение,
и она исправлена: Лила теперь такой же потребитель, как QA Quest.

## Как это работает на домене

`aka-gst.ru/Caddyfile` проксирует два семейства маршрутов в сервис аккаунтов,
не срезая префикс:

```
handle /api/auth/*      -> accounts:8080
handle /api/progress/*  -> accounts:8080
```

Кука `aka_auth` выставлена с `Path=/`, поэтому одна сессия обслуживает и
`/leela/`, и `/qa-quest/`, и любой следующий проект на этом же origin.

## Что вызывает QA Quest

`src/auth.js` использует ровно эти маршруты:

| Метод и путь | Тело запроса | Ответ |
|---|---|---|
| `GET /api/auth/me` | — | `{"authenticated": false}` или `{"authenticated": true, "email": "...", "email_verified": true}` |
| `POST /api/auth/register` | `{"email", "password"}` (пароль от 12 символов) | `201 {"created": true, "verification_required": true}`, `409 email_unavailable` |
| `POST /api/auth/verify` | `{"token"}` | `{"verified": true}` и открытая сессия |
| `POST /api/auth/login` | `{"email", "password"}` | `{"authenticated": true, "email"}`, `401`, `403 email_not_verified`, `429 too_many_attempts` |
| `POST /api/auth/logout` | — | `{"authenticated": false}` |
| `GET /api/progress/qa-quest` | — | `{"state": {...} или null, "updatedAt": 1756400000}` |
| `PUT /api/progress/qa-quest` | `{"state": {...}}` | `{"saved": true, "updatedAt": ...}` |

Если `GET /api/auth/me` не отвечает или отдаёт не-JSON, клиент переходит в
состояние `offline`: кнопка входа объясняет, что сервис недоступен, а прогресс
продолжает жить в `localStorage`. Ни один урок при этом не ломается — это
проверяется каждый раз, когда сайт открывают локально без бэкенда.

## Как объединяется прогресс

Слияние делает клиент (`mergeState` в `src/store.js`), а не сервер. Сервер
хранит `state` как непрозрачный JSON и о его формате ничего не знает — поэтому
формат прогресса можно менять, не трогая сервис аккаунтов.

- решённые задачи объединяются по принципу «решено хотя бы где-то»;
- у общей задачи сохраняется более раннее время решения;
- открытые ступени объединяются по «открыто хотя бы где-то»;
- рекорд серии берётся максимальный, текущая серия — из более свежего дня;
- сохранённый код берётся из более свежего состояния.

Потерять решённую задачу при переключении устройств нельзя.

## Порядок внедрения

1. `cd ops/accounts && docker compose up -d --build` — сервис на `zakriva-net`.
2. Выложить обновлённый `Caddyfile` и перезагрузить Caddy.
3. `python3 migrate_from_leela.py …` — перенести существующие учётные записи.
4. В QA Quest ничего не менять: клиент найдёт эндпоинты сам.

Если сервис аккаунтов стоит на другом хосте, путь задаётся через
`window.QA_QUEST_API` до загрузки `src/main.js`, и на сервисе нужно разрешить
CORS с credentials.
