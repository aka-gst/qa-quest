# QueQuest 10.0 — AUTOMATION COMMONS

Дата прохода: 2026-09-19.

## Зачем этот слой существует

WORLD GRID 9.0 дал игроку правильную фантазию роста: новый класс проблемы сначала
нужно исследовать, а после mastery знакомую причину можно чинить сразу кодом.
10.0 делает следующий шаг: **исправление не должно исчезать вместе с аварией**.
Игрок получает возможность превратить понятую причинность в reusable-автомат,
сохранить его и дать миру реально жить на нём.

Главный ритм:

`ПОНЯЛ ПРИЧИНУ → СОБРАЛ ПОВЕДЕНИЕ → ПРОЖИЛ СМЕНУ → СОХРАНИЛ BLUEPRINT →
СМЕШАЛ BLUEPRINTS → ОПТИМИЗИРОВАЛ ПО ЖЕЛАНИЮ → ЗАМЕНИЛ КОНСТРУКТОР PYTHON-КОДОМ`.

Код здесь снова не является входным билетом. Он становится самым быстрым способом
управлять уже понятой системой.

## Game-first правила

1. **Сначала человеческая ситуация.** В `A+` игрок видит «когда поток стал больше,
   чем линия успевает», а не `load > capacity`.
2. **Выбор раскрывается контекстно.** До выбора `КОГДА?` действие недоступно. После
   выбора показываются только 2–3 осмысленных действия, а не весь словарь системы.
3. **Память появляется только когда нужна.** `IDEMPOTENCY` физически требует блок
   «помнить уже виденные ID»; stateless-схема не проходит.
4. **Любое рабочее решение — победа.** Игрок не обязан минимизировать cost или
   complexity, чтобы двигаться дальше.
5. **Оптимизация — добровольная игра.** После победы можно сделать схему дешевле,
   быстрее или компактнее и сравнить результат.
6. **Blueprint действительно reusable.** Сохранённая схема загружается обратно в
   builder для ремикса и позже работает в CITY AUTOPILOT.
7. **После mastery интерфейс можно выбросить.** После двух живых city-days игрок
   получает один `autopilot(event, state)` и семь скрытых behavioral checks.

## Четыре authored automation-истории

### 01 · Утро без паники

Фабрика знает burst. Теперь игрок не чинит его вручную: автомат сам замечает
перегрузку. Есть как минимум два валидных решения — `queue` или дополнительный
worker — с разной стоимостью/скоростью.

### 02 · Память о побочном эффекте

Retry приносит тот же `order-id`. Простого условия недостаточно: автомату нужна
память `seen`. Это вводит state через потребность мира, а не через определение.

### 03 · Чистый контекст

Одновременно приходят устаревшие знания и payload без обязательного поля. Игрок
впервые собирает автомат из двух независимых правил.

### 04 · Ночной автопилот

Опасный tool, больная ветка и уже идущий chunked-ответ требуют трёх разных границ.
Это первая маленькая автономная система, которая не становится «смелее человека».

## CITY AUTOPILOT

После 4/4 blueprints открывается seed-based день. Он смешивает знакомые типы событий
и задаёт ограниченный `capacity`. Все blueprints сначала включены, но игрок может
отключать лишние прямо в библиотеке. Это создаёт понятный второй уровень игры:
не «знаю ли я правило», а «какой минимальный набор автоматов нужен этому дню».

Seed воспроизводим. XP за один seed выдаётся один раз. Успех не требует идеального
score — достаточно пережить день без непокрытых событий и переполнения capacity.

## CODE DEPLOYMENT

После двух успешных city-days открывается master-path. Игрок пишет настоящий Python:

```python
def autopilot(event, state):
    family = event.get("family")
    # уже знакомые причины → твои решения
```

Скрытые проверки покрывают семь знакомых семейств:

- flow/backpressure;
- duplicate side-effect;
- knowledge freshness/provenance;
- schema boundary;
- tool authority;
- resilience/degraded path;
- streaming.

Для duplicate-case проверяется состояние между двумя вызовами, поэтому текстовая
имитация без памяти не проходит.

## Долгая петля

AUTOMATION COMMONS должен давать replay не количеством вопросов, а композициями:

- новый working blueprint;
- ремикс старого blueprint;
- другая валидная архитектура;
- добровольная оптимизация;
- новый seed-day;
- ограниченный capacity;
- переход от визуальных блоков к Python.

Это заимствует не контент, а полезный дизайн-принцип open-ended puzzle games:
сначала достаточно любого работающего решения, а затем игрок сам выбирает, хочет ли
он оптимизировать систему. Второй принцип — маленькие понятные элементы должны
собираться в более крупные абстракции, пока игрок не начинает управлять системой
целиком.

## Маленький asset-budget

10.0 не превращает QueQuest в коллаж. Добавлены только два функциональных значка из
Kenney Game Icons (`signal3`, `save`) и используется уже существующий Kenney UI-click.
Game Icons опубликованы Kenney под CC0. Локальная provenance/license заметка лежит
рядом с файлами. Значки декоративно поддерживают текст и никогда не являются
единственным носителем состояния.

## Что намеренно не объявляется доказанным

Автотесты могут доказать логику, persistence, behavioral contracts и отсутствие
битых DOM-связей. Они не доказывают, что игроку хочется ещё один city-day или что
оптимизация ощущается как удовольствие. Для human playtest 10.0 важны три вопроса:

1. Понимает ли полный новичок `КОГДА → ТОГДА` без знания слов `queue/idempotency`?
2. После первого рабочего решения хочется ли добровольно сделать схему лучше?
3. После пары визуальных дней ощущается ли Python-autopilot как заслуженная сила,
   а не как внезапный экзамен?
