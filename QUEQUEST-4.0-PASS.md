# QueQuest 4.0 — release pass

Дата сборки: 2026-09-19.

## Зачем этот pass

4.0 не расширяет обязательный syllabus ещё одной главой. Он усиливает самое рискованное место всей игры — первые 30–60 минут для человека, который никогда не программировал, не разрушая темп для игрока с опытом.

Главный принцип: **сначала хочется действовать и экспериментировать; термин и код появляются как имя уже понятого поведения**.

## Что изменено

### 1. Первые три ящика стали игровым обучением машины

- терминал показывает `LEARNING PATH` из трёх наблюдений;
- каждый ручной маршрут добавляет физически видимую ячейку;
- на 3/3 появляется `PATTERN READY`;
- автоматизация ощущается как payoff за уже освоенное действие, а не как лекция о циклах.

### 2. Мост `МИР → СМЫСЛ → PYTHON`

Для ранних концептов (`print`, `if/for`, `while/list`, `def`) сначала формулируется проблема мира, затем смысл решения, и только потом минимальная форма Python. В compact-режиме промежуточное объяснение скрывается.

### 3. Одна игра для новичка и опытного

- `A+` — guided density: ориентир появляется после реального простоя, а CPython error получает человеческий runtime-hint;
- `A−` — compact density: те же правила и задания, но подсказки заметно позже и без промежуточной колонки смысла;
- переключатель не меняет награды, задачи, проверки или мир;
- новый прогресс сбрасывает таймер подсказки, поэтому активному игроку интерфейс не мешает.

### 4. SORTER BAY — первая добровольная системная игрушка

После освоения `IF` можно открыть небольшой сортировочный цех:

`SOURCE → PASS / HOLD`

- 8 наблюдаемых ящиков на scenario;
- правило выбирается по смыслу, а не по названию Python-конструкции;
- неверная схема реально сортирует груз и показывает конкретные misroute-контрпримеры;
- Python скрыт до работающего решения;
- поздние версии той же игрушки добавляют два признака и `and / or / not`;
- бонус полностью опционален и не блокирует основную кампанию.

### 5. Ошибка остаётся настоящей ошибкой Python

Игра не заменяет `SyntaxError`, `NameError`, `IndentationError` собственными псевдоошибками. В `A+` рядом показывается короткая подсказка из CPython runner; в `A−` остаётся сырое диагностическое доказательство. Код игрока автоматически не переписывается.

## Design sources, применённые как принципы

- Jesse Schell: проектировать не линейное усложнение, а кривую интереса и осмысленные выборы;
- Scott Rogers: обучение лучше растягивать по самой игре, постоянно вводя новое действие/gear/gameplay, а не складывать всё в отдельный tutorial-level;
- практикумы пользователя по AI-агентам: наблюдаемое доказательство важнее заявления системы — этот же принцип перенесён в ранний Python и Sorter Bay.

Тексты, иллюстрации, код книг и практикумов в релиз не копировались.

## Что нельзя честно утверждать до живого playtest

- что первый час уже идеально держит абсолютного новичка;
- что общая игра гарантированно длится 20 часов для любого игрока;
- что тайминги adaptive coach оптимальны;
- что Sorter Bay добровольно хочется перепроходить несколько раз.

Следующий критерий качества — наблюдение за реальным человеком: где он действует без просьбы, где экспериментирует после успеха и где перестаёт понимать причинно-следственную связь.
